## 0. 한 문장 정의

**지영랩 웹사이트는 "중·고등 영어 수업/내신 대비에 바로 쓸 수 있는 자료를, 시험·교재 단위로 찾아서, 샘플로 품질을 확인하고, 구매 후 즉시 내려받는" 디지털 교육자료 판매 플랫폼이다.**

핵심 설계 원칙:

1. **검색 단위 = 고객이 실제로 찾는 단위.** 고객은 "Grammar 자료"가 아니라 "고2 2026년 9월 모의고사 변형문제", "중3 동아(윤) 5과 워크북"을 찾는다. 사이트 구조와 SEO가 모두 이 단위를 축으로 한다.
2. **품질은 샘플로 증명한다.** 교육자료는 써보기 전엔 품질을 알 수 없다. 모든 유료 상품은 샘플(미리보기)을 갖는다.
3. **디지털 상품은 즉시성 + 재다운로드 + 수정판 배포가 핵심 가치.** 구매 후 내 자료실에서 언제든 받고, 오류 수정판이 나오면 자동으로 최신본을 받는다.
4. **운영자 1인이 유지 가능해야 한다.** 상품이 시험 회차마다 수십 개씩 늘어나는 구조이므로, 상품 등록은 "한 건씩 손으로"가 아니라 **일괄 등록**이 가능해야 한다.

## 2. 핵심 Customer Journey

### J1. 검색 유입 → 구매 (주력 경로)
```
네이버/구글 검색 "고2 9월 모의고사 변형문제"
 → 시험 허브 페이지 (/exams/mock/2026-09-g2)  ← SEO 랜딩
 → 해당 시험의 상품 목록 (변형문제 / 워크북 / 어휘 / 패키지)
 → 상품 상세 (구성, 문항 수, 형식, 미리보기, 샘플 다운로드)
 → 장바구니 → 결제 → 내 자료실에서 즉시 다운로드
 → (이메일) 수정판 알림 / 다음 회차 출시 알림 → 재구매
```

### J2. 콘텐츠 유입 → 무료자료 → 회원 → 구매 (육성 경로)
```
블로그 글 "고1 3월 모의고사 출제 경향 분석" 유입
 → 글 하단 무료자료 CTA (해당 시험 어휘 리스트 무료)
 → 무료 다운로드 (회원가입/이메일 필요)
 → 뉴스레터·알림 수신 동의
 → 다음 시험 시즌 알림 → 유료 상품 구매
```

### J3. 직접 방문 / 재방문 (단골 경로)
```
홈 → "이번 시험 자료" 기획전 or 카탈로그 필터 (학년·시험·교재·유형)
 → 패키지 구매 or 이전 구매 상품의 다음 회차 구매
```

### J4. 학원 대량/기관 구매
```
상품 상세 or 문의 페이지 → "학원 라이선스 / 대량구매 문의"
 → 문의 접수 (학원명, 강사 수, 필요 자료, 증빙 종류)
 → (MVP) 운영자 수동 견적 → 계좌이체 + 세금계산서
 → (확장) 학원 라이선스 상품 직접 결제
```

### J5. 구매 후 지원
```
내 자료실 → 다운로드 / 수정판 재다운로드
 → 오류 제보 / 환불 문의 (주문 단위로 연결된 문의)
```

## 5. 상품 / Catalog 구조

### 5.1 엔터티 모델 (개념)

```
Product (판매 단위)
 ├─ type: SINGLE | PACKAGE
 ├─ title, slug, summary, description(본문), status: DRAFT | PUBLISHED | ARCHIVED
 ├─ price, sale_price, is_free
 ├─ taxonomy (아래 5.2)
 ├─ specs: page_count, question_count, has_answer_key, has_explanation
 ├─ preview_images[], sample_file (공개)
 ├─ files[] → ProductFile (비공개, 구매자만)
 │     └─ versions[] → FileVersion (v1, v1.1 수정판 …, changelog)
 ├─ license_tier: PERSONAL | ACADEMY   [D3]
 └─ (PACKAGE인 경우) items[] → Product(SINGLE) 참조

Collection (탐색/SEO 단위 — 상품을 묶어 보여주는 허브)
 ├─ kind: MOCK_EXAM | SUNEUNG | EBS_BOOK | TEXTBOOK_LESSON | CAMPAIGN(기획전)
 ├─ slug, title, intro_body(SEO 본문), metadata(year, month, grade, publisher …)
 └─ products[]  (태그/필터 기반 자동 + 수동 고정)

FreeResource (무료자료) — Product(is_free=true)로 통합 관리 [권장]
Order, OrderItem, Entitlement(사용자 × 상품 다운로드 권한), DownloadLog
Post (블로그), Inquiry (문의), User
```

**핵심 구조 결정:**
- **Product(판매 단위)와 Collection(탐색 단위)을 분리한다.** 상품 하나가 여러 허브에 동시에 노출될 수 있다(예: "고2 9월 모의고사 어휘" 상품 → 9월 모의고사 허브 + 고2 어휘 기획전).
- **무료자료도 가격 0원인 Product로 통합한다.** 다운로드 권한(Entitlement)·내 자료실·다운로드 로그를 그대로 재사용할 수 있어, 별도 시스템을 만들 필요가 없다.
- **파일은 버전을 가진다.** 오류 수정판을 올리면 기존 구매자도 최신본을 받는다(디지털 교육자료의 핵심 신뢰 요소).
- **패키지는 단품의 참조 묶음이다.** 패키지 구매 시 포함 단품 각각에 대한 Entitlement가 생성된다 → 내 자료실에서 단품 단위로 보인다.

### 5.2 분류 체계 (Taxonomy)

| 축 | 값 (예) | 용도 |
|---|---|---|
| **학년** | 중1, 중2, 중3, 고1, 고2, 고3 | 필터, 허브 |
| **출처 유형** | 모의고사(교육청), 평가원(6·9월/수능), EBS 연계, 교과서(내신), 자체 커리큘럼 | 1차 탐색 축 |
| **출처 상세** | 연도·월 / 교재명 / 출판사·저자·단원 | 허브 slug 생성 |
| **자료 유형** | 변형문제, 워크북, 서술형, Grammar, Vocabulary, 분석노트, 모의고사형 테스트 | 필터 |
| **파일 형식** | PDF, HWP, DOCX | 필터, 배지 |
| **난이도** (선택) | 기본, 표준, 심화 | 필터 |

**slug 규칙(SEO 안정성):** 사람이 읽을 수 있고 바뀌지 않는 영문 slug를 쓴다. 예: `/materials/2026-09-mock-g2-transform-set-a`, `/exams/mock/2026-09-g2`. 한글 제목은 바뀌어도 slug는 유지한다.

### 5.3 예상 상품 라인업 (구조 검증용 예시)

| 라인 | 단품 예시 | 패키지 예시 |

## 6. 무료자료와 유료자료의 관계

무료자료는 "공짜로 나눠주는 것"이 아니라 **세 가지 역할을 가진 마케팅 자산**으로 설계한다.

| 유형 | 역할 | 형태 | 게이트 | 유료 연결 |
|---|---|---|---|---|
| **F1. 상품 샘플** | 품질 증명 | 유료 상품의 일부 페이지 PDF + 미리보기 이미지 | **게이트 없음** (공개) — 구매 장벽을 낮추는 게 목적 | 같은 페이지의 구매 버튼 |
| **F2. 리드 마그넷** | 회원·이메일 확보 | 독립적으로 쓸 만한 완결 자료 (예: 회차별 어휘 리스트, 문법 요약표) | **로그인 필요** (무료 회원가입) | 다운로드 후 "이 시험 전체 변형문제" 추천 + 다음 시즌 알림 |
| **F3. 콘텐츠 부록** | SEO 글의 전환 장치 | 블로그 글에 딸린 워크시트 | 로그인 필요 | 글 + 자료 하단 관련 상품 CTA |

**원칙**
- 샘플(F1)은 게이트를 두지 않는다. 품질 확인을 막으면 구매율이 떨어진다.
- 독립 완결 무료자료(F2, F3)는 로그인 게이트를 둔다. 이게 이메일 리스트(재구매 채널)의 원천이다.
- 무료자료 다운로드는 유료와 같은 Entitlement로 기록한다 → "무료자료를 받은 사람" 세그먼트로 마케팅할 수 있다.
- 광고성 메일 수신 동의는 **가입 동의와 분리된 선택 항목**으로 받는다(정보통신망법).

## 7. 구매 전환 구조

### 7.1 전환 깔때기와 장치

| 단계 | 이탈 원인 | 대응 장치 |
|---|---|---|
| 유입 → 탐색 | 원하는 시험/교재 자료를 못 찾음 | 시험·교과서 허브, 필터, 검색, 홈 시즌 기획전 |
| 탐색 → 상세 | 상품 카드 정보 부족 | 카드에 학년·문항 수·형식 배지·가격 표시 |
| 상세 → 장바구니 | 품질 불확실 | 미리보기 이미지, 공개 샘플, 구성 명세, 업데이트 이력, 제작 원칙 링크 |
| 장바구니 → 결제 | 가입 귀찮음, 결제수단, 증빙 | 간편 가입(카카오 로그인 권장 `[D7]`), 간편결제(카카오페이·네이버페이·토스), 현금영수증/세금계산서 선택 |
| 결제 → 만족 | 다운로드 불편, 오류 | 결제 직후 다운로드 화면 + 이메일, 내 자료실, 수정판 자동 반영 |
| 만족 → 재구매 | 다음 회차 출시 모름 | 시리즈 알림(이메일·카카오 알림톡 `[확장]`), 내 자료실 추천 |

### 7.2 객단가 장치
- **패키지 할인:** 상세 페이지에서 "이 상품이 포함된 패키지" 노출 + 절약액 표시
- **학원 라이선스:** 개인용 대비 높은 가격의 다인원 라이선스 `[D3]`
- **쿠폰 / 시즌 할인:** 확장 단계

### 7.3 결제 이전 단계(MVP)의 전환 처리
PG(결제대행) 계약 전에는 결제 기능을 켤 수 없다. MVP의 처리 방식(권장안):

- 결제 플로우(장바구니·주문·권한 부여·다운로드)는 **구조와 코드까지 구현하되, 실제 PG 호출은 feature flag로 막아 둔다.**
- 결제가 켜지기 전 상품 상세의 구매 버튼은 운영자가 선택하는 **임시 모드**로 동작한다. `[D1]`
  - (a) "구매 문의" → 문의 폼(상품 자동 첨부) → 계좌이체 → 운영자가 수동으로 권한 부여
  - (b) 외부 판매 채널(스마트스토어 등)로 링크 연결
- PG 계약이 끝나면 설정만 바꿔 사이트 내 결제로 전환한다.

### 7.4 디지털 상품 법적 요건 (설계 반영 필수)
- **전자상거래법 청약철회 제한:** 다운로드한 디지털 콘텐츠는 청약철회를 제한할 수 있으나, **사전에 명확히 고지하고 결제 시 동의**를 받아야 한다. 샘플 제공은 제한의 근거를 강화한다. → 결제 화면에 동의 체크, 환불정책 페이지, "다운로드 전에는 환불 가능" 상태 구분(DownloadLog 필요)
- **사업자 정보 표시:** 상호, 대표자, 사업자등록번호, **통신판매업 신고번호**, 주소, 연락처 (footer)
- **개인정보처리방침** 필수, 수집 항목 최소화
- **불법 공유 억제:** 구매 파일에 구매자 정보(이메일/주문번호) **워터마크** 삽입, 다운로드 횟수·기간 제한, 서명된(만료되는) 다운로드 URL `[D5]`

## 8. Blog / SEO 구조

### 8.1 SEO 전략: "시험·교재 단위 허브"가 주력, 블로그는 보조

교육자료 검색은 **long-tail·시즌성**이 매우 강하다("2026 고2 9월 모의고사 31번 변형"). 따라서:

1. **허브 페이지(Collection)가 1차 SEO 랜딩이다.** 시험 회차·교과서 단원마다 고유 URL, 고유 제목·설명·본문(시험 개요, 지문 목록, 출제 포인트 요약)을 가진다. 상품이 늘수록 자동으로 랜딩 페이지가 늘어나는 구조(programmatic SEO)다.
2. **블로그는 상위 퍼널 + 전문성 신호**다. 시험 분석·학습법 글이 허브와 상품으로 내부 링크를 보낸다.
3. **내부 링크 규칙:** 블로그 → 허브 → 상품, 상품 → 허브(breadcrumb), 허브 ↔ 이전/다음 회차.

### 8.2 블로그 카테고리 (초안)
- 시험 분석 (모의고사·수능 회차별 출제 경향)
- 내신 대비 (교과서 단원 분석, 학교 시험 대비 전략)
- 수업 노하우 (강사 대상: 자료 활용법, 수업 설계)
- 문법·어휘 (개념 정리 글 — 상시 검색 수요)
- 지영랩 소식 (신규 자료, 업데이트)

### 8.3 기술 SEO 요구사항 (Phase 2에서 구현 방식 결정)
- 서버 렌더링된 HTML (검색봇이 JS 없이 본문을 읽을 수 있어야 함)
- 페이지별 title/description/canonical, Open Graph(카카오톡 공유 미리보기 중요)
- 구조화 데이터: `Product`(가격·재고), `BreadcrumbList`, `Article`, `FAQPage`, `Organization`
- `sitemap.xml`(허브·상품·글 자동 포함), `robots.txt`
- **네이버 서치어드바이저 등록 + 네이버용 메타**: 국내 교사 고객은 네이버 검색 비중이 높다 → 구글과 동일 비중으로 대응
- (운영) 네이버 블로그를 쓰고 있다면 원문은 사이트 블로그, 네이버 블로그는 요약 + 링크 방식 권장 `[D9]`

## 9. 운영자 관점 관리 요구사항

| 영역 | MVP 필수 | 확장 |
|---|---|---|
| **상품 등록/수정** | 메타데이터 입력, 가격, 상태(초안/공개/보관), 분류 지정, 미리보기 이미지·샘플 업로드, 판매 파일 업로드(비공개 저장) | 예약 공개, 일괄 가격 변경 |

| **허브/기획전** | 허브 소개 본문 편집, 홈 "이번 시험 자료" 섹션 교체 | 기간 한정 기획전 |
| **블로그** | 글 작성(마크다운 또는 에디터), 카테고리, 대표 이미지, 관련 상품/무료자료 연결, 공개/예약 | — |

| **주문/권한 (결제 전)** | **수동 권한 부여** (계좌이체 고객에게 상품 다운로드 권한 부여) | — |
| **주문/권한 (결제 후)** | 주문 목록, 결제 상태, 환불 처리(권한 회수), 다운로드 로그 확인 | 매출 리포트, 쿠폰 |
| **회원** | 회원 목록, 수신 동의 여부 | 세그먼트 메일 발송 |
| **접근 통제** | 관리자 로그인 (운영자 1~2명) | 역할 분리 |

**관리 도구 원칙:** 별도 관리자 시스템을 무겁게 만들지 않는다. "운영자 1인이 웹 화면에서 상품 하나를 5분 안에, 회차 하나를 30분 안에 등록"을 목표로 한다. 구체적인 도구(헤드리스 CMS vs 자체 admin)는 Phase 2에서 결정한다.

## 12. Phase 1 결론 → Phase 2 입력값

Phase 2(기술 구조)에서 반드시 충족해야 할 요구사항을 정리하면:

1. **SEO:** 서버 렌더링, 대량의 허브 페이지 자동 생성, 구조화 데이터, 네이버 대응
2. **데이터:** Product/Collection/FileVersion/Entitlement/Order를 다루는 관계형 데이터 모델
3. **파일:** 공개(미리보기·샘플) vs 비공개(판매 파일) 저장소 분리, 서명된 만료 URL, (선택) PDF 워터마크
4. **인증:** 이메일 + 소셜(카카오) 로그인 확장 가능
5. **결제:** PG 교체 가능한 어댑터 구조, flag로 켜고 끄기
6. **운영:** 1인 운영 가능한 관리 화면 + 일괄 등록
7. **비용:** 초기 저비용(D14), 트래픽 시즌 급증 대응
8. **유지보수:** 과도한 아키텍처 배제 — 단일 애플리케이션 + 관리형 서비스 조합 우선
